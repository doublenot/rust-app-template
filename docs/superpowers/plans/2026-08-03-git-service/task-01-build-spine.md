### Task 1: Build spine — vendored git2

Nothing in this task is git *logic*. It buys one thing: proof that a fully self-contained
libgit2 + libssh2 + OpenSSL builds on this machine and reports the four capability bits every
later task depends on. Doing it now means a build-toolchain failure surfaces here, in a
40-line commit, instead of in Task 7 when there is 2 000 lines of unfinished code on the branch.

**Before you start — prerequisites.** The vendored OpenSSL build needs `perl` and `make` on
`PATH` in addition to a C toolchain. `perl` in particular is *not* implied by "a C compiler",
and its absence produces an opaque `openssl-src` error. Check first:

```bash
perl --version && make --version && cc --version
```

On Debian/Ubuntu: `sudo apt-get install -y build-essential perl pkg-config`.
On macOS: Xcode Command Line Tools ship all three. On Windows MSVC no OpenSSL is built at all
(WinHTTP + WinCNG), so the MSVC toolchain alone is enough.

**Expect a slow build.** Step 6 compiles OpenSSL, libssh2, and libgit2 from source. On an
8-core box that is **~1 m 45 s** wall-clock the first time (~+80 s over the current baseline;
OpenSSL is roughly 70 % of it). It is cached in `target/` afterwards and does not recur.
Do not assume the command has hung.

**Files:**
- Modify: `Cargo.toml:10-28` — add `gethostname` and `git2` to `[dependencies]` (alphabetical,
  between `fd-lock` and `image`), and a new `[target.'cfg(unix)'.dependencies]` block above the
  existing `[target.'cfg(windows)'.dependencies]` block.
- Modify: `Cargo.lock` — regenerated by cargo, committed (CI runs `--locked`).
- Create: `src/git/mod.rs`
- Modify: `src/main.rs:3-8` — add `mod git;` to the module block.

**Interfaces:**

- Consumes: nothing. This is the first task that touches `Cargo.toml` or `src/git/`. It is
  independent of Task 0 (`main.rs` → `host.rs`): the `mod` declaration block stays in `main.rs`
  under that split, so the two tasks do not collide even if Task 0 has not landed.

- Produces (later tasks rely on all of these existing):
  - `git2 = { version = "0.21", features = ["https", "ssh", "vendored-libgit2"] }` — the
    `git2` crate at 0.21 with network transports. Consumed by tasks 6, 7, 8, 9.
  - `gethostname = "1"` → `gethostname::gethostname() -> std::ffi::OsString`. Consumed by
    task 6 to populate `ops::Identity.hostname`.
  - `openssl-sys = { version = "0.9", features = ["vendored"] }` under
    `[target.'cfg(unix)'.dependencies]` — no Rust code names it; it exists purely to unify the
    `vendored` feature across the dependency graph.
  - `src/git/mod.rs` exists and is reachable as `crate::git`. Each later module registers
    itself by adding one `pub mod <name>;` line to this file when it lands (task 3 adds
    `pub mod error; pub mod secret; pub mod util;`, task 4 adds `pub mod registry; pub mod
    state;`, and so on). **Task 1 adds no `pub mod` lines** — the files do not exist yet and
    the crate would not compile.
  - `mod git;` in `src/main.rs`.

> **CI note — not this task's file.** `.github/workflows/*` is owned by Task 12, which adds
> `perl` and `pkg-config` to the Linux `apt-get install` line. Until Task 12 lands, the
> ubuntu leg of CI may fail in `openssl-src`. That is expected and tracked; do not edit the
> workflow here.

- [ ] **Step 1: Write the failing test**

Create `src/git/mod.rs` with exactly this content. It is `cargo fmt`-clean as written — do not
re-wrap the `assert!` calls onto one line, rustfmt will split them straight back.

```rust
//! Git service.
//!
//! Root of the host-side git subsystem. Nothing lives here yet beyond the build-spine
//! tripwire below; each later module registers itself by adding its own
//! `pub mod <name>;` line to this file as it lands.

#[cfg(test)]
mod tests {
    /// Guards the `git2` feature list in `Cargo.toml`, not git2 itself.
    ///
    /// git2 0.21 declares `default = []`. A bare `git2 = "0.21"` therefore compiles,
    /// links, and passes every local-only test while producing a libgit2 with no HTTPS
    /// and no SSH transport: `clone`/`fetch`/`push` against a real remote fail at
    /// runtime with "unsupported URL protocol", possibly months after the dependency
    /// was added. Dropping `vendored-libgit2` is the same trap pointed the other way —
    /// the build silently links whatever libgit2 the build machine happens to have, so
    /// the shipped .deb/.dmg/.msi depends on a system library the user does not have.
    /// libgit2 reports all four capabilities at runtime, so one assertion converts both
    /// silent regressions into a red test.
    #[test]
    fn libgit2_is_vendored_with_network_transports() {
        let v = git2::Version::get();
        assert!(
            v.vendored(),
            "libgit2 must be the vendored build; Cargo.toml needs the `vendored-libgit2` feature: {v:?}"
        );
        assert!(
            v.https(),
            "libgit2 must be built with HTTPS; Cargo.toml needs the `https` feature: {v:?}"
        );
        assert!(
            v.ssh(),
            "libgit2 must be built with SSH; Cargo.toml needs the `ssh` feature: {v:?}"
        );
        assert!(
            v.threads(),
            "libgit2 must be thread-aware; git work runs on tokio's blocking pool: {v:?}"
        );
    }
}
```

Then register the module in `src/main.rs`. The block currently reads:

```rust
mod chrome;
mod config;
mod internal_server;
mod settings;
mod supervisor;
mod tray;
```

Insert `mod git;` after `mod config;` so the list stays alphabetical:

```rust
mod chrome;
mod config;
mod git;
mod internal_server;
mod settings;
mod supervisor;
mod tray;
```

- [ ] **Step 4: Run the test and watch it fail the assertion**

Run: `cargo test --bin chrome-host-app git::tests`

This compiles libgit2 from source (~15 s — a local-only libgit2 with no TLS and no SSH is
cheap). Expected: FAIL, and note *how* it fails — the code compiled and linked, and only the
runtime capability report gives the problem away.

```
running 1 test
test git::tests::libgit2_is_vendored_with_network_transports ... FAILED

failures:

---- git::tests::libgit2_is_vendored_with_network_transports stdout ----

thread 'git::tests::libgit2_is_vendored_with_network_transports' panicked at src/git/mod.rs:27:9:
libgit2 must be built with HTTPS; Cargo.toml needs the `https` feature: Version { major: 1, minor: 9, rev: 6, crate_version: "0.21.0", vendored: true, threads: true, https: false, ssh: false, nsec: true }

test result: FAILED. 0 passed; 1 failed; 0 ignored; 0 measured; 0 filtered out
```

Two things to read out of that `Version { .. }` dump:

- `https: false, ssh: false` — exactly the silent local-only build the test exists to catch.
  Every network verb in tasks 7 and 8 would have failed at runtime with
  `unsupported URL protocol`.
- `vendored: true` even without the `vendored-libgit2` feature. `libgit2-sys` probes for a
  system libgit2 via pkg-config and *falls back* to vendoring when it finds none — so on a
  machine that does have `libgit2.pc` installed, this same step fails on the `vendored()`
  assertion instead, with `vendored: false`. Either way the test is red; the feature makes
  the outcome deterministic across machines instead of dependent on what is installed.

- [ ] **Step 5: Add the real dependency lines**

Replace the naive `git2 = "0.21"` line and add the two neighbours. After this edit
`Cargo.toml` reads (only the changed regions shown; everything else is untouched):

```toml
[dependencies]
anyhow = "1"
axum = "0.8"
dirs = "6"
fd-lock = "4"
gethostname = "1"
# git2 0.21 has `default = []` — a bare `git2 = "0.21"` is LOCAL-ONLY: clone/fetch/push over
# the network are silently unavailable and only fail at runtime. `vendored-libgit2` keeps the
# shipped .deb/.dmg/.msi from depending on a system libgit2 that is not there.
git2 = { version = "0.21", features = ["https", "ssh", "vendored-libgit2"] }
image = { version = "0.25", default-features = false, features = ["png"] }
```

and, immediately above the existing `[target.'cfg(windows)'.dependencies]` block:

```toml
# libssh2-sys declares a NON-OPTIONAL openssl-sys dependency on cfg(unix) — and cfg(unix)
# includes macOS. libgit2's own HTTPS backend on macOS is SecureTransport, so git2's
# `vendored-openssl` feature (gated to cfg(all(unix, not(macos)))) does NOT cover libssh2's
# copy. Declaring openssl-sys directly here unifies the `vendored` feature across the whole
# graph on every unix target, so a clean machine with no system libssl builds. Windows uses
# WinHTTP + WinCNG and pulls in no OpenSSL at all.
[target.'cfg(unix)'.dependencies]
openssl-sys = { version = "0.9", features = ["vendored"] }

[target.'cfg(windows)'.dependencies]
winreg = "0.55"
```

`gethostname` is not referenced by any Rust code yet — task 6 uses it for
`ops::Identity.hostname`. An unused dependency produces no warning from rustc or clippy, so it
is safe to land it here with the rest of the spine rather than in the middle of task 6.

- [ ] **Step 7: Prove the vendoring reaches every target, including macOS**

The macOS leg is the one everybody gets wrong ("macOS uses SecureTransport, so no OpenSSL is
needed" — false, because libssh2 still wants it). `cargo tree` resolves for a target without
that target's toolchain being installed, so all three can be checked from one machine.

Run:

```bash
cargo tree -i openssl-src
cargo tree -i openssl-sys --target aarch64-apple-darwin
cargo tree -i openssl-sys --target x86_64-pc-windows-msvc
```

Expected — `openssl-src` (the vendored-source build dependency) is present, meaning OpenSSL is
compiled from source rather than linked from the system:

```
openssl-src v300.6.1+3.6.3
[build-dependencies]
└── openssl-sys v0.9.117
    ├── git2 v0.21.0
    │   └── chrome-host-app v0.1.0 (...)
    ├── libgit2-sys v0.18.7+1.9.6
    │   └── git2 v0.21.0 (*)
    ├── libssh2-sys v0.3.2
    │   └── libgit2-sys v0.18.7+1.9.6 (*)
    └── chrome-host-app v0.1.0 (...)
```

Expected on `aarch64-apple-darwin` — `openssl-sys` **is** in the graph (this is the
[VERIFY] from spec §12.1; git2's own optional `openssl-sys` is gated off on macOS, so the two
edges that remain are libssh2-sys's non-optional one and our direct one, which is what carries
the `vendored` feature):

```

│   └── git2 v0.21.0
│       └── chrome-host-app v0.1.0 (...)
├── libssh2-sys v0.3.2
│   └── libgit2-sys v0.18.7+1.9.6 (*)
```

Expected on `x86_64-pc-windows-msvc` — no OpenSSL at all:

```
warning: nothing to print.

To find dependencies that require specific target platforms, try to use option `--target all` first, and then narrow your search scope accordingly.
```

If the macOS invocation prints `warning: nothing to print.`, the `[target.'cfg(unix)']` block
is missing or misspelled (`cfg(unix)`, not `cfg(target_family = "unix")` — both are valid TOML
but only the first matches the spec and the README's removal recipe). Go back to Step 5.
